# Fold（折页）产品需求文档 PRD

> 版本 v1.0 · 2026-11-17
> 依据：`fold-mail-brainstorm.md` + 已确认的 UI 原型（`designs/fold-fusion.html`）
> 定位一句话：**本地优先、无 WebView、可脚本化的安静邮件工作台**

---

## 1. 产品定位

### 1.1 一句话
给开发者和内容重度用户的小而快的邮件工作台：打开即用、断网可用、搜索极快、隐私可见。

### 1.2 不做什么（决定做什么）
- 不做"又一个 Thunderbird 替代品"——不做日历、联系人、网盘、内置浏览器
- 不做自己的邮件服务器
- 不做 AI 写邮件（v1）；若做，只做本地小模型的分类建议，正文不出本机
- 不做 WebView / 浏览器内核

### 1.3 用户画像
| 画像 | 特征 | 核心诉求 |
|---|---|---|
| 开发者 | 多账号（Gmail / Outlook / QQ / 163 / 企业邮），习惯键盘 | 快、脚本化、命令面板、本地数据 |
| 内容重度用户 | 订阅多、通知多、邮件量大（万级） | 智能分组、全文搜索、归档效率 |
| 隐私敏感用户 | 关注追踪像素、外部图片、加密 | 隐私可见、拦截可反馈、端到端加密 |

---

## 2. 产品原则

1. **本地优先**：已同步邮件、附件、索引全在本机。断网可读、可搜、可写草稿，联网后补发。
2. **无 WebView**：正文用 Rust 渲染器绘制，脚本不执行，远程图片默认不加载。这是"快"与"安全"的共同来源。
3. **键盘优先，但不劝退鼠标**：快捷键全覆盖，每个操作也有可见入口。
4. **可脚本化**：规则、模板、自动分类用配置 + 小脚本表达，不逼用户点设置面板。
5. **v1 只做邮件**：把一个收件箱做到极致。

## 3. UI 规范（已由原型确认）

原型：`designs/fold-fusion.html`（Aerion 气质：深板岩底 + 紫罗兰强调）。

### 3.1 布局：四栏
```

│图标栏 │ 账号/文件夹  │ 会话列表          │ 正文                         │
│ 54px │ 206px      │ 352px            │ flex                         │
│      │            │                  │                              │
│ ✉ ▤ ◔ ▧│ Fold       │ 全部收件箱  9封   │ 项目进展 · 周五前给一版          │
│      │ ✎ 写邮件    │ [搜索框  /]       │ Alice Chen <alice@…> 今天10:23 │
│ ⌘ ◐ ? ⚙│ oliver@…   │ ● Alice   10:23  │ ────────────────────────────  │
│      │ 空间        │   项目进展…       │ [✓ 已拦截3个追踪像素 · 2个链接]  │
│      │  全部收件箱9 │ ● Bob     09:15  │                              │
│      │  人 /通知/订阅│   Re: 合同…  ★   │ 正文居中，最大宽度 720px        │
│      │ 整理        │ ○ GitHub  08:52  │ [附件卡] [快速回复]             │
│      │  星标/稍后/归档│                  │                              │
└──────┴────────────┴──────────────────┴──────────────────────────────┘
```

### 3.2 明确的布局约束（用户已两次强调）
- **不设独立顶栏**：搜索并入会话列表顶部，写邮件并入左栏，命令/主题/帮助并入图标栏
- **不设底部工具条**：密度与字体切换走命令面板，不放常驻栏
- **图标全部 SVG**（线性 stroke 风格），不用 emoji 或字符符号
- 文件夹分组用「空间 / 整理」两组语义标签，未读数用数字不用红点轰炸

### 3.3 视觉语言
| 项 | 规范 |
|---|---|
| 深色（默认） | 深板岩 `#14141B`，面板 `#191922`，文字 `#E8E6F0` |
| 强调色 | 紫罗兰 `#8B5CF6`；选中态 `#2A2145`；未读竖条 `#A78BFA` |
| 浅色（备选） | 纸白 `#FFFFFF`，强调 `#7C4DE6`,强调浅底 `#EDE5FD` |
| 字体 | 系统字体（SF Pro / PingFang SC）；正文可切衬线（Songti SC / Noto Serif SC） |
| 圆角 | 组件 6–8px，浮层 12px；头像圆形；动效仅 120–180ms |
| 头像 | 彩色圆形，取发件人首字母；无头像时用中性底色 |
| 星标 | 每行行尾常驻，未标星为空心，标星为实心金色 |

### 3.4 关键组件
- **隐私状态条**：正文顶部展示"已拦截 N 个追踪像素 · M 个外部链接"，可展开看具体域名并逐个「允许 / 加载」
- **附件卡**：图标 + 文件名 + 大小，点击预览
- **快速回复**：正文底部内联编辑器，展开发送，10 秒可撤销
- **命令面板（⌘K）**：既执行命令也搜邮件；上下选择、回车执行、Esc 关闭
- **写信浮层**：独立浮层，极简工具栏；底部固定「定时发送 / 发送后 10 秒撤销」

### 3.5 键盘流
| 键 | 动作 | 键 | 动作 |
|---|---|---|---|
| `j` / `k` | 下 / 上移动 | `r` / `a` / `f` | 回复 / 全部回复 / 转发 |
| `↵` | 打开邮件 | `c` | 写邮件 |
| `e` | 归档 | `/` | 搜索 |
| `s` | 星标 | `⌘K` | 命令面板 |
| `u` | 撤销 | `?` | 快捷键帮助 |

## 4. 功能需求

优先级：**P0** = v1 必须；**P1** = v1 应有；**P2** = v1.5 及以后。

### 4.1 账号与收发
| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-01 | 多账号统一管理，支持 IMAP/SMTP、OAuth2 与"应用密码"两条路 | P0 | 可同时添加 Gmail、Outlook、QQ、163 账号并收发 |
| FR-02 | 自动配置：走 `autoconfig.xml` + ISPDB 查询，减少手填 | P0 | 输入邮箱地址后自动填充服务器参数；失败可手动配置 |
| FR-03 | 凭据安全：token 存系统 keyring，不落明文 | P0 | 配置文件中无明文密码；keyring 不可用则拒绝保存 |
| FR-04 | 统一收件箱：跨账号聚合视图 | P0 | 左栏「全部收件箱」展示所有账号未读 |
| FR-05 | 后台同步：打开即读本地，网络操作异步完成后通知界面 | P0 | 断网可打开应用并读已缓存邮件；联网后自动补同步 |
| FR-06 | IMAP IDLE 推送 + 弱网心跳保活 | P1 | 新邮件秒级到达；断线自动重连 |
| FR-07 | JMAP 支持（Fastmail 等） | P2 | — |

### 4.2 收件箱与整理
| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-10 | 智能分组：默认切「人 / 通知 / 订阅」三栏，规则可覆盖 | P0 | 列表可按三个分组过滤；分组规则可编辑 |
| FR-11 | 会话（thread）视图 | P1 | 同一主题的往来邮件聚合，可展开折叠 |
| FR-12 | 星标 / 稍后处理 / 归档，批量操作可撤销 | P0 | 三种状态可切换；批量操作后 `u` 可完整撤销 |
| FR-13 | 紧凑 / 舒适两档密度 | P1 | 命令面板可切换，列表密度即时变化 |
| FR-14 | 规则用 TOML 声明，进阶可挂 Rhai 脚本 | P1 | 改配置文件即可新增分类规则，无需重新编译 |

### 4.3 全文搜索（杀手锏）
| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-20 | 本地全文索引（Tantivy），断网可搜 | P0 | 拔网线后搜索仍返回结果 |
| FR-21 | 支持发件人 / 主题 / 正文 / 附件名过滤 | P0 | 输入关键词秒级返回；支持 `from:` `has:attachment` 等限定 |
| FR-22 | 搜索即命令：命令面板内直接搜邮件 | P1 | ⌘K 输入关键词可搜到邮件并回车打开 |
| FR-23 | 百万级邮件下搜索响应 < 500ms | P1 | 以 100 万封样本压测达标 |

### 4.4 隐私与安全
| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-30 | 每封邮件显示拦截的追踪像素数与外部链接数 | P0 | 正文顶部状态条准确显示数量 |
| FR-31 | 远程图片默认不加载；可临时或永久允许某域名 | P0 | 默认无外链请求；点「加载」才请求；允许后写入规则 |
| FR-32 | 无 WebView：正文由 Rust 渲染器绘制，脚本不执行 | P0 | HTML 邮件中的 `<script>` 不执行；渲染失败回退纯文本 |
| FR-33 | 正文 HTML 经 ammonia 清洗 | P0 | 表单、事件属性、危险 URL 被剥离 |
| FR-34 | 提供"在外部浏览器打开"的安全出口 | P1 | 浏览器打开时有明确风险提示 |
| FR-35 | Autocrypt 开箱加密（Sequoia），密钥交换藏在邮件头 | P1 | 两个 Fold 客户端互发可自动建立加密；UI 区分"已加密"与"支持但未配置" |
| FR-36 | 手动导入 OpenPGP 公钥 | P2 | — |

| FR-43 | 附件拖拽 | P1 | 文件拖入写作浮层即添加 |
| FR-44 | 内联快速回复 | P1 | 正文底部展开编辑器，回复走同一发送管线 |

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-50 | ⌘K 命令面板：执行命令 + 搜邮件 | P0 | 覆盖全部键盘动作；输关键词可搜邮件 |
| FR-51 | 快捷键全覆盖 | P0 | 见 3.5 键盘流 |
| FR-52 | `foldctl` CLI 与桌面端共用核心库 | P1 | 可列邮件、搜索、快速回复、导出 `.eml` |

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|

## 5. 非功能需求

| 类别 | 指标 |
|---|---|
| 性能 | 冷启动 < 1s；打开已缓存邮件 < 100ms；搜索百万级 < 500ms |
| 资源 | 空闲内存 < 150MB；无 WebView 带来的低占用是核心卖点 |
| 隐私 | 无遥测；远程内容默认阻断；凭据仅存 keyring |
| 可靠性 | 断网可读写草稿；同步失败可重试不丢数据；所有破坏性操作可撤销 |
| 兼容性 | macOS / Windows / Linux；QQ / 163 / Gmail / Outlook / 企业邮自动配置覆盖 |
| 无障碍 | 所有操作有可见入口；键盘可达；对比度符合 WCAG AA |
| 安全 | 正文沙箱渲染；依赖审计；二进制可复现构建（目标） |

## 7. 风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 正文渲染 | `blitz` 面对真实 HTML 邮件仍可能出错 | 纯文本回退 + "在外部浏览器打开"出口 |
| UI 框架成熟度 | iced 复杂列表滚动 / 富文本选区可能要自己补；GPUI 更漂亮但 API 不稳 | M0 早期技术验证，不及时切换 |
| IMAP 现状 | 各家 IDLE、搜索、文件夹命名有偏差 | 按账号池化连接 + 心跳保活；按服务商适配层 |
| Autocrypt 兼容 | 覆盖率有限，不能承诺"自动加密所有邮件" | UI 文案诚实区分加密状态 |
| 范围失控 | 最大风险不是技术，是忍不住塞日历 / 联系人 | 以本文档"不做什么"为硬约束 |

## 8. 开放问题

1. UI 最终选 `iced` 还是 GPUI？—— M0 预研决定
2. 正文渲染 `blitz` 是否满足真实邮件？—— M0 用 100 封真实邮件样本验证
3. 会话视图的聚合规则如何跨账号？—— M1 设计，M2 落地
4. 规则脚本用 Rhai 还是纯 TOML 声明式优先？—— 默认 TOML，Rhai 作为进阶可选项

## 附录 A：术语

| 术语 | 含义 |
|---|---|
| Autocrypt | 在普通邮件头里交换密钥的端到端加密协议，无需密钥服务器 |
| IDLE | IMAP 的推送机制，长连接等待新邮件 |
| ISPDB | Thunderbird 维护的邮件服务商配置数据库 |
| Tantivy | Rust 全文搜索引擎，Lucene 的 Rust 实现 |
| outbox | 本地待发送队列，`send_at` 决定何时真正投递 |
| WebView | 内嵌浏览器内核；Fold 明确不使用 |

## 附录 B：UI 决策记录（来自原型迭代）

1. 顶栏不单独占一栏 —— 搜索并入列表、写邮件并入左栏、命令/主题并入图标栏（用户两次强调）
2. 底部不设常驻工具条 —— 密度与字体切换走 ⌘K 命令面板
3. 图标一律 SVG 线性风格，不用 emoji / 字符符号
4. 融合 Foxmail 的四栏专业骨架 + Gmail 的克制气质 + Aerion 的深色紫调
5. 每封邮件隐私状态可见且可反馈，是区别于其他客户端的核心差异点
