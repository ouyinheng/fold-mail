# Fold — 一个用 Rust 写的邮箱，头脑风暴

> 定位一句话：**本地优先、无 WebView、可脚本化的安静邮件工作台**。
> 不做"又一个 Thunderbird 替代品"，而是做给开发者和内容重度用户的、打开就能用的小工具。

---

## 1. 名字

**首选：Fold（折页 / 信笺）**

- 字面义：把信折起来放进信封，天然贴合邮件。
- 函数式编程里 `fold` 是把一堆东西收敛成一个结果——正好是"把散落各处的消息收进一个收件箱"的隐喻。
- 短、好记、CLI 里敲起来顺手（`fold`），中文叫"折页"也说得通。
- 备选：`Vellum`（羊皮纸，质感路线）、`Letterbox`（英式信箱）、`Wren`（鹪鹩，小而快）、`Ferris Post`（玩 Rust 螃蟹梗，太闹，放弃）。

---

## 2. 产品原则（决定不做什么）

1. **本地优先**：所有已同步的邮件、附件、索引都在本机。断网可读可搜可写草稿，联网后自动补发。
2. **无 WebView、无浏览器内核**：正文用 Rust 渲染器画，脚本不执行，远程图片默认不加载。这是"快"和"安全"的共同来源，也是和 Electron 系客户端最大的差异。
3. **键盘优先，但不劝退鼠标**：快捷键全覆盖，同时每个操作都有可见入口。
4. **可脚本化**：规则、模板、自动分类都用配置 + 小脚本表达，不逼用户点设置面板。
5. **v1 只做邮件**：日历、联系人、文件网盘统统往后放。先把一个收件箱做到极致。

## 3. 功能设想

### v1（能用、想用）

- 多账号统一收件箱：IMAP/SMTP 为主，OAuth2 和"应用密码"两条路都打通（QQ 邮箱、163、Gmail、Outlook 都能接）。自动配置走 `autoconfig.xml` + ISPDB 查询，减少手填服务器。
- **本地全文搜索**：Tantivy 建索引，支持发件人/主题/正文/附件名过滤，秒级响应，断网照样搜。这是我认为最值得先做的差异化功能——大部分轻量客户端搜索都很难用。
- **智能分组**：收件箱默认切成「人 / 通知 / 订阅」三栏，规则可覆盖。规则用 TOML 声明，进阶用户可挂 Rhai 脚本。
- **隐私报告**：每封邮件显示"拦截了 N 个追踪像素、M 个外部链接"，一键允许/永久允许某个域名。把"防追踪"从开关变成可见反馈。
- **Autocrypt 开箱加密**：用 Sequoia + `sequoia-autocrypt`，密钥交换藏在正常邮件头里，不需要用户先去密钥服务器；同时支持手动导入 OpenPGP 公钥。
- 写作体验：模板 / 片段、定时发送、发送后 10 秒撤销（本质是本地 outbox 里的 `send_at`，撤销就改回草稿）、附件拖拽。
- 会话（thread）视图、星标/稍后处理/归档、批量操作均可撤销。
- 键盘流：`Cmd+K` 命令面板（既能执行命令也能搜邮件）、`j/k` 移动、`r/a/f` 回复/全部回复/转发、`e` 归档、`s` 星标、`u` 撤销、`/` 搜索。
- `foldctl` CLI 与桌面端共用核心库：列邮件、搜索、快速回复、导出邮件为 `.eml`。对脚本党很重要。

### v1.5（有意思但不阻塞首发）

- JMAP 支持（Fastmail、Tutanota 类服务商）。
- 规则市场：共享 TOML 规则片段。
- 本地 HTTP API（默认关闭），让 Obsidian / 自动化脚本能读收件箱。
- 移动端：核心库复用，UI 另做。

### 明确不做

- 日历、联系人、网盘、内置浏览器。
- 自己的邮件服务器。
- AI 写邮件（至少 v1 不做；如果做，也只做本地 small model 的分类建议，不把正文发给云端）。

## 4. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 / 构建 | Rust 2024 edition，cargo workspace | 核心库与 UI / CLI 分离 |
| 异步运行时 | `tokio` | 生态最全 |
| IMAP | `async-imap` + rustls，IDLE 做推送 | 符合标准协议 |
| SMTP | `lettre` | 事实标准 |
| MIME 解析 | `mail-parser` | 快，容错好 |
| OAuth2 | `oauth2` + `keyring` 存 token | 凭据不落明文 |
| 本地存储 | `rusqlite`（SQLite），附件存文件 + DB 记路径 | 单文件、可靠、好备份 |
| 全文索引 | `tantivy` | Rust 里的 Lucene，离线搜索质量高 |
| 正文渲染 | `blitz`（Dioxus 的 HTML/CSS 渲染器）+ `ammonia` 清洗 | 无 WebView，脚本不执行；渲染失败回退纯文本 |
| 加密 | `sequoia-openpgp` + `sequoia-autocrypt` | 纯 Rust，不依赖用户装 GnuPG |
| 规则脚本 | TOML 声明式为主，`rhai` 可选 | 简单规则不写代码，复杂规则能写 |
| UI | `iced`（wgpu 渲染） | 纯 Rust、跨平台；若追求更精致排版可评估 GPUI，但 API 稳定性是风险 |
| 配置 | TOML + XDG 目录 | 可读、可 diff、可版本管理 |
| 错误 / 日志 | `thiserror` / `anyhow` + `tracing` | 常规组合 |
| 测试 | `insta` 快照 + `wiremock` 模拟 IMAP/SMTP 交互 | 协议层必须可回归 |
| 发布 | `cargo-dist` 生成各平台安装包 | 省事 |

### 架构草图

```
┌──────────────────────────────────────────────┐
│  fold-desktop (iced)      foldctl (CLI)      │  ← 只管交互
└───────────────┬──────────────────┬───────────┘
                │ 本地 API (无需网络)
┌───────────────▼──────────────────────────────┐
│                  fold-core                   │
│  sync(IMAP/JMAP)  send(SMTP)  search(tantivy) │
│  rules(rhai)  crypto(sequoia)  store(sqlite) │
└───────────────┬──────────────────────────────┘
                │
        ┌───────▼────────┐
        │ 本机 SQLite + 附件目录 + 索引目录      │
        └────────────────┘
```

关键约束：**UI 永远只读本地数据，任何网络操作都异步完成再通知界面**。打开一封邮件时从 SQLite 立即渲染，同步在后台跑。这是"快"的手感来源。

## 5. UI 设计

### 视觉语言：纸与墨

- 亮色：暖白纸张底色（#F7F5F0），墨色文字（#1F2328），单一强调色靛蓝（#3D5AFE）。
- 暗色：深板岩（#14171C），文字（#E6E8EB），强调色降饱和。
- 系统字体（SF Pro / PingFang SC），正文邮件可切衬线字体（宋体 / Noto Serif SC），强化"读信"的感觉。
- 留白充足，圆角小（6–8px），动效只做 120ms 淡入，不花哨。

### 三栏布局

```
┌──────────┬────────────────────┬─────────────────────────────┐
│ 账号/目录 │ 会话列表            │ 正文                        │
│ 220px    │ 360px              │ flex                        │
│          │                    │                             │
│ 全部收件箱│ ○ Alice  项目进展   │  项目进展                    │
│  人  12  │   "周五前给一版…"    │  Alice <alice@…>  今天 10:23 │
│  通知 5  │ ○ 通知  GitHub      │  ─────────────────────────── │
│  订阅 23 │ ○ Bob   Re: 合同    │  [已拦截 3 个追踪像素]        │
│          │                    │                             │
│ 星标     │                    │  正文居中栏，最大宽度 760px   │
│ 稍后处理 │                    │                             │
│ 归档     │                    │                             │
├──────────┴────────────────────┴─────────────────────────────┤
│ ⌘K 命令  │  已同步 10:24  ·  2 封未读   ·  j/k 移动          │
└─────────────────────────────────────────────────────────────┘
```

- 左侧只放"空间"不放花哨图标，未读数用数字不用红点轰炸。
- 邮件列表：头像圈 + 加粗发件人 + 主题 + 一行摘要，日期右对齐；未读用左侧细竖条，不用整行加粗。
- 阅读区顶部是隐私状态条：加密徽标 / 拦截追踪数 / 外部图片按钮，点开能看到具体域名。
- 写作窗口独立浮层，极简工具栏；底部固定"定时发送 / 撤销发送"开关。
- 紧凑 / 舒适两档密度切换，适配小屏和大量邮件场景。

## 6. 路线图（按能拿出手的节奏）

1. **M1 骨架**：cargo workspace、fold-core 存储层、IMAP 同步 + SQLite 缓存、只读 UI。
2. **M2 收发**：SMTP 发送、草稿、会话视图、附件、账号设置向导。
3. **M3 差异化**：全文搜索、分组规则、隐私报告、命令面板、CLI。
4. **M4 加密与打磨**：Autocrypt、OpenPGP、快捷键全覆盖、性能与无障碍。
5. **M5 发布**：cargo-dist 打包、autoconfig 覆盖主流中文邮箱、文档与截图。

---

## 7. 主要风险

- **正文渲染**：`blitz` 面对真实世界 HTML 邮件仍会出错，必须准备纯文本回退和"在外部浏览器打开"的安全出口。
- **iced 的成熟度**：复杂列表滚动、富文本选区可能要自己补；GPUI 更漂亮但 API 变动频繁。这是最值得早期做技术验证的一点。
- **IMAP 的现实现状**：各家服务商的 IDLE、搜索、文件夹命名都有偏差，异步连接管理要按账号池化并做心跳保活。
- **Autocrypt 的兼容性**：覆盖率有限，不能承诺"自动端到端加密所有邮件"，UI 文案要诚实区分"已加密"和"支持加密但未配置"。
- **范围失控**：最大的风险不是技术，是忍不住把日历/联系人塞进来。

## 8. 如果只记住三件事

1. 名字叫 **Fold**，中文"折页"。
2. 杀手锏是 **本地全文搜索 + 隐私可见 + 无 WebView 的快**。
3. 架构上 **core 与 UI 彻底分离**，桌面端和 CLI 共用同一个本地优先内核。
